# Archvela v0.1.0-alpha.1 — Draft release notes

> **STATUS: RELEASE CANDIDATE DRAFT — NOT PUBLISHED.** This file does not authorize creating a tag, GitHub Release, package, deployment or paid model run. The intended tag is `v0.1.0-alpha.1` only **after** all release gates and explicit repository-owner approval. Check the exact release commit before publication.

Archvela is a scenario-first frontend architecture Skill for independent developers and AI coding assistants. The first Alpha focuses on **auditable architecture decisions**, not a claim of production-ready autonomous software creation.

## Highlights

- **62 architecture scenarios in six domains**, covering websites and commercial presentation, business tools, digital twins, professional visualization, browser games and geospatial products. These are mostly **Chinese-language reference materials**, not 62 runnable projects.
- **Three runnable examples and generated starters** for V3-02 (cinematic marketing site), V3-14 (SaaS operations workspace) and V3-26 (illustrative home digital twin). The digital-twin demonstration is **not construction-ready CAD/BIM**.
- **Portable Agent Skill** named `archvela-architect`, with English-first discovery metadata, Chinese-source routing and context-based React/Vue/Astro/Next.js/other framework recommendations.
- **Offline Python helpers** for scenario lookup, architecture drafts, a machine-readable plan contract and a safe no-overwrite project starter generator.
- **L0/L1 checks**: Python validation, installer testing for 20 agent targets, four lockfile audits, dependency review for PRs, CodeQL, generated starter smoke builds, and Chromium browser E2E for the three examples.
- **Experimental benchmark infrastructure**: 12 curated tasks, baseline/treatment operator cards, signed randomized V2 pilot manifests, redacted review packets, evidence hashes and failure-aware summaries. **No actual model effect has been demonstrated.**

## Install (preview; public repository already available)

Run from a project directory with Node.js/npm and access to GitHub:

```bash
npx --yes skills@1.7.4 add kunlong-luo/archvela --skill archvela-architect \
  --agent codex --agent claude-code --agent opencode --copy --yes
```

The command above points at the **repository's current default branch** and may change later. It is a convenience example, **not a release-SHA-pinned installation**. For a reproducible release after the tag has actually been published, follow the pinned-commit instructions in [the project quickstart](../GETTING-STARTED.md), substituting the verified release commit. Do not use a nonexistent tag or assume the installer verifies actual native client discovery.

To examine architecture drafts without any model/API use:

```bash
python3 .agents/skills/archvela-architect/scripts/scenes.py --query "company website"
python3 .agents/skills/archvela-architect/scripts/new_project_docs.py \
  --scene V3-26 --project sample-home --output ./scratch/sample-home --plan-json
```

From a local **Archvela repository checkout**, preview the three code templates with `python3 scripts/archvela_create.py list`; the generator refuses overwrites and requires `--write` to create files.

## Limitations and precautions

- 20 installer targets means **L1 filesystem/CLI compatibility**. It does not mean 20 live AI agents successfully discovered the Skill (L2) or delivered better software (L3).
- The benchmark harness is a **study scaffold, not a published head-to-head result**. No Codex/Claude Code/OpenCode win-rate, score or token savings is claimed.
- Detailed 62-scenario V3 references are mostly Chinese; English entrypoint/guide are not full translations.
- All architectural choices and example contents need review for requirements, devices, browser support, licenses and provenance. Any medical, structural engineering, finance or safety-critical use needs independent professional verification.
- Before any tag: complete the owner-managed [Release Candidate Checklist](../ALPHA-RELEASE-CHECKLIST.md), including **third-party rights review**, main protection, real client smoke proof, license inventory and final explicit release authorization.
