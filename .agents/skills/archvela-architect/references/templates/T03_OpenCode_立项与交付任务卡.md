# T03｜OpenCode 单人开发任务卡（复制到每个项目）

## A. 立项任务：先审计，不强迫迁移

```text
你现在是本仓库的前端工程实施助手。先阅读 AGENTS.md、README.md、
00_通用_单人产品工厂与前端架构规范.md、V3全场景索引、
对应的01–06领域卷及T01/T02模板。

第1步：只读审计仓库当前框架、package manager、构建器、路由、组件、
真实功能、性能测试和资源许可证。对已有项目，禁止因为“统一技术栈”
直接迁移 Next.js、Vite、Rsbuild、R3F 或更换数据持久化策略。

第2步：从 V3-xx 场景选一个主场景，填写 ADR，设计用户旅程、
有特色的 Design Tokens/视觉签名、Feature 边界，明确不用的技术。

第3步：列出四层分包：packages（源码复用）、features（业务模块）、
chunks（JS按路由/能力）、asset packs（图像/视频/GLB/瓦片/音频）。
不要引入无实际需求的重渲染引擎和动效依赖。

第4步：实现一个真实可验收的垂直切片。必须有正常/空/错误/加载状态、
移动端体验、Reduced Motion/无WebGL时适用的退化路径，
以及可重复的类型/单测/E2E/构建检查。

第5步：输出实际报告：变更文件、能力完成度、依赖变化、分包统计、
Lighthouse及目标设备性能、失败用例和剩余风险。

任何删库、外部发布、外部账号操作、付费资源下载、部署、仓库写入
都遵守仓库AGENTS权限边界与用户授权。先给出拟变更和验收清单。
```

## B. PR 交付单
- [ ] ADR 已填写，框架选择有理由且未无故迁移
- [ ] 真正完成一个用户任务，不使用假功能冒充产品完成度
- [ ] Design Tokens 和关键组件有项目独立识别度
- [ ] 重要 JS Chunk 与重资产延迟加载有测试证据
- [ ] 已完成空状态/错误/超时/权限失败/无WebGL回退
- [ ] 已测试手机/桌面和减少动画偏好
- [ ] 类型检查、lint、构建、单元/E2E通过
- [ ] 版权、数据来源、3D资产、字体/视频许可证有记录
- [ ] 没有 Token/敏感信息，未触发未授权对外行为
- [ ] 文档与代码版本一致，列出未完成项目
